# Security & privacy risk register

Scale: **L**ikelihood and **I**mpact rated Low / Medium / High *before* controls; **Residual** is our view after the controls in this build. "Where" points to the code that implements the control.

## Threats

| # | Threat | L | I | Controls in this build | Where | Residual | Further treatment (production) |
|---|---|---|---|---|---|---|---|
| R1 | **Credential stuffing / brute force** on login | H | H | Per-IP rate limit (20 req / 15 min on auth routes); bcrypt cost 12; generic "Invalid email or password"; dummy-hash compare for unknown emails (no timing oracle); failed logins audit-logged with hashed email; password policy (≥12 chars, common-password deny-list, must not contain email name) | `middleware/rateLimit.js`, `controllers/authController.js`, `utils/validators.js` | M | TOTP MFA (stretch, not built); per-account lockout/backoff; HIBP breached-password check; alerting on `auth.login_failed` spikes |
| R2 | **XSS leading to session/token theft** | M | H | JWT only in an `httpOnly` cookie (never in JS-readable storage); React escapes output; CSP (`default-src 'self'`, `frame-ancestors 'none'`, restricted `connect-src`); `helmet` headers on API | `middleware/auth.js`, `frontend/next.config.js` | L–M | Nonce-based CSP to remove `'unsafe-inline'` for scripts |
| R3 | **CSRF** (cross-site cookie is `SameSite=None`) | M | H | Origin allow-list + mandatory `X-Requested-With` on every unsafe method (forces a CORS preflight that other origins fail); CORS allow-list, never `*` | `middleware/csrf.js`, `server.js` | L | Serve API on a same-site subdomain to use `SameSite=Lax/Strict` |
| R4 | **Broken access control / IDOR** — executive reads another executive's data, or escalates role | H | H | `requireAuth` reloads the user from the DB on every request (role and active flag are never taken from the client); `requireRole` on every protected route; executive endpoints use `/me` (no ids to tamper with); document ownership check returns **403 for both "not yours" and "doesn't exist"** (no existence oracle); self-registration always `executive`; strict schemas reject extra fields (`role`, `status`); admins cannot change their own role; reviewers cannot see drafts | `middleware/auth.js`, `middleware/rbac.js`, `controllers/documentController.js`, `routes/index.js` | L | Automated authz test matrix per route (partially in `test/api.test.js`) |
| R5 | **Insecure file upload** — malware, polyglots, oversized files, public exposure | H | H | Extension **and** MIME **and** magic bytes must agree (PDF/PNG/JPG/DOCX only); 5 MB limit enforced while streaming; validated in memory, never written to local disk; random storage id (client filename kept as sanitised metadata only); Cloudinary `type: authenticated` (no public URL exists); downloads only via an authorised route returning a **5-minute signed URL**; SHA-256 recorded at upload; 10 docs/profile cap; every upload/download audited | `middleware/upload.js`, `services/storageService.js`, `controllers/documentController.js` | M | AV scanning (e.g. ClamAV / Cloudinary add-on) before a file becomes viewable; DOCX macro stripping; CDR |
| R6 | **Audit-log tampering / repudiation** | M | H | Single write path (`auditService.record`); entries are hash-chained (`hash = SHA256(prevHash + canonicalJSON(entry))`); unique `seq` (deletions show up as gaps, concurrent writers cannot fork); Mongoose hooks block update/delete; `GET /api/audit/verify` (admin) recomputes the chain and reports the first broken entry; verify runs are themselves audited | `services/auditService.js`, `models/AuditLog.js` | M | Truncating the *tail* of the chain is not detectable from the chain alone → periodically anchor the head hash externally (e.g. write to WORM/object-lock storage or a signed timestamp); DB role for the API with insert+find only on `auditlogs` |
| R7 | **Data breach of PII** (DB or storage compromise, over-exposure in UI) | M | H | Atlas encryption at rest + TLS; documents in separate private storage; minimisation (only vetting fields collected); masked names/emails in the reviewer queue; full record only on single view, which is audit-logged (`profile.viewed`); no PII in audit metadata, push payloads, logs or service-worker cache; IPs stored only as salted hashes; generic client errors, no stack traces | `controllers/reviewController.js`, `utils/mask.js`, `services/notificationService.js`, `public/sw.js` | M | Atlas IP allow-list (currently `0.0.0.0/0` for PoC); field-level encryption for referee contact data and ID metadata; secrets in a vault; DLP alerts |
| R8 | **NDPA non-compliance** — consent, purpose, retention, data-subject rights | M | H | Explicit granular consent (vetting / sharing), never pre-ticked, stored append-only with `{granted, version, timestamp, ipHash}`; submission blocked without vetting consent; privacy notice (purpose, lawful basis, retention, rights, DPO) shown at consent step and `/privacy`; self-service **export** (JSON) and **erasure** (purge files, anonymise, audit); rectification via edit while draft/MIR | `controllers/profileController.js`, `components/PrivacyNotice.js`, `app/account/page.js` | M | Automated retention job (24 months post-outcome, see Known Limitations); DPIA; records of processing; DPO workflow for consent withdrawal after submission; cross-border transfer assessment for Atlas/Cloudinary regions |
| R9 | **Offline data left on a shared device** | M | M | Only draft step data + last profile stored in IndexedDB; cleared on logout, erasure, and when a different user signs in; API responses never in Cache Storage | `lib/offlineQueue.js`, `lib/auth.js` | M | Encrypt IndexedDB contents with a session-derived key; idle timeout |
| R10 | **Offline replay corrupts data** (duplicates, stale overwrites) | M | M | Idempotency key per queued save (duplicate = no-op); `clientSavedAt` (clamped to server time) prevents an older save overwriting a newer one; replay is in step order and stops on network/401 errors | `controllers/profileController.js`, `lib/offlineQueue.js` | L | — |
| R11 | **Race between reviewers** (lost updates, illegal transitions) | M | M | Server-side transition table; conditional `findOneAndUpdate` on the *current* status (second writer gets 409); mandatory note for MIR / Rejected | `controllers/reviewController.js`, `utils/taxonomy.js` | L | Reviewer assignment / locking |

| R13 | **Denial of service / resource abuse** | M | M | Global and auth rate limits; 100 KB JSON limit; 5 MB single-file uploads; document count cap | `server.js`, `middleware/*` | M | Render free tier has no autoscaling — acceptable for PoC |

## NDPA 2023 principles → controls

| NDPA principle (s.24) | How the build implements it |
|---|---|
| **Lawfulness, fairness & transparency** | Consent is the lawful basis, captured explicitly per purpose with no pre-ticked boxes. The privacy notice is shown before consent and kept at `/privacy`. A versioned consent record (`consentVersion`) ties each grant to the notice text the person saw. |
| **Purpose limitation** | Two separate purposes (vetting; sharing a verified profile with clients), each with its own consent. Reviewers cannot open drafts (data not yet submitted for vetting). |
| **Data minimisation** | The wizard collects only vetting-relevant fields (no date of birth, no national ID number fields; the ID is a document). Names and emails are masked in list views. Push payloads, audit metadata and logs carry no PII. IPs are stored as salted hashes only. |
| **Accuracy** | Server-side validation on every step. The executive can rectify while in draft and whenever a consultant requests more information. Submission re-validates the whole profile. |
| **Storage limitation** | Retention period is stated in the notice (24 months post-outcome). Erasure is self-service. *Automated retention purge is not yet built* (Known Limitations). |
| **Integrity & confidentiality** | TLS everywhere; encryption at rest; httpOnly session; RBAC + ownership checks; private document storage with short-lived signed URLs; SHA-256 per document; tamper-evident audit chain. |
| **Accountability** | Every material action is audit-logged, including reads of PII (`profile.viewed`, `document.downloaded`). The chain can be verified on demand. Consent history and status history are kept (without personal content) after erasure as evidence of lawful processing. |

### Data-subject rights (NDPA Part VI)

| Right | Implementation |
|---|---|
| Access / portability | `GET /api/profile/me/export`: account, profile, consents, document metadata, notifications, and the audit entries about the subject, as JSON. Audited as `data.exported`. |
| Rectification | Edit any step while `draft` or `More Information Required`. |
| Erasure | `POST /api/profile/me/delete-request` (password re-entry): purges Cloudinary files (aborts with 502 if any purge fails, so the request can be retried), anonymises the profile and account, deletes notifications and push subscriptions, signs the user out. Audited as `data.erased`. |
| Withdraw consent | Re-record choices while editable; after submission, via DPO or erasure (self-service withdrawal post-submission is a next step). |
